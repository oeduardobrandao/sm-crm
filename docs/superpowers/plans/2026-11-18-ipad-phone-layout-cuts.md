# iPad phone layout: phone-view cuts audit (Task 10)

Touch tablets now get the CRM phone shell. Anything a phone view hides that the desktop
offered is a loss on tablets. A "cut" is a capability (action, data or setting) present on
desktop and absent from the phone view. A different layout of the same capability is not a
cut.

## How the audit was done

- **Phone branches:** every `if (isPhone|phone|isPhoneEditor|isMobile)` early return in
  `apps/crm/src` (about 100 sites). A script then listed the handlers that desktop JSX wires
  (`on*={handleX|openX|setX|toggleX|onX}`) and the phone block never references. Every hit
  in a primary flow (Início, Entregas, posts, Clientes, Tarefas, Financeiro, Mensagens,
  Agenda) was read by hand; hits elsewhere were read where they looked like actions rather
  than state setters.
- **Other names:** `!isDesktop`, `isDesktop ?`, `variant === 'phone'`,
  `layout === 'phone'`, `!isPhone &&`, `isPhone ? null`.
- **`useIsDesktop(N)` with N > 768:** every one is `901`: Leads, Financeiro, Automações,
  Contatos, Arquivos, Entregas. All of them choose table versus cards, or aside versus sheet.
  A tablet takes the phone branch before any of them, so none hides a capability.
- **Raw width queries:** `matchMedia('(max-width: 1100px|900px)')` and `innerWidth` in
  ClienteDetalheNav, AgendaTab, AnalyticsConta and TourOverlay. These are layout and scroll
  only.
- **Copy:** `computador` / `desktop` across the CRM sources and the pt/en locales.

"Read" means the desktop and phone code were both opened. "Diff" means the handler diff
found nothing missing and a spot check agreed.

## Step 1b: Tailwind width variants inside the phone shell

`md:`/`lg:`/`xl:` utilities in shell code. None was verified in a real browser: jsdom cannot
evaluate media queries. Task 12's walk should look at the rows marked "renders in phone
shell".
